# L05 — Эрсдэлийн төлөвлөгөө

| № | Эрсдэл | Магадлал / Нөлөө | Хариуцах хүн | Эрт илрүүлэх шинж | Авах арга хэмжээ |
|---|---|---|---|---|---|
| R1 | Цаг хүрэлцэхгүй байх | Дунд / Өндөр | Би | Төлөвлөсөн milestone хугацаанаасаа хоцрох | Must ажлыг түрүүлж дуусгаж, Should ажлыг дараа шилжүүлэх |
| R2 | Интернэт тасрах | Дунд / Дунд | Би | GitHub нээгдэхгүй, push хийхгүй байх | Local файл болон commit-оо хадгалж, сүлжээ сэргэсний дараа push хийх |
| R3 | Git branch/merge алдаа | Дунд / Өндөр | Би | Conflict, буруу branch, хоосон PR | Branch нэр, diff, status-ийг шалгаж, нэг нэгээр нь засах; merge хийхээс өмнө review авах |
| R4 | Код/шаардлагыг ойлгохгүй байх | Өндөр / Дунд | Би | Алдааны шалтгааныг тайлбарлаж чадахгүй байх | Жижиг жишээгээр турших, баримт унших, багшаас асуух; AI-ийн зөвлөгөөг заавал шалгах |
| R5 | Хамрах хүрээ хэт томрох | Дунд / Дунд | Би | Нэмэлт боломж үндсэн ажлыг хойшлуулах | Scope-ийг Must/Should гэж ангилж, үндсэн ажлын дараа нэмэлт боломж хийх |

## Эрсдэлийг хянах

- Долоо хоног бүр эрсдэлийн төлөвийг шалгана.
- Эрсдэл бодитоор гарвал болсон огноо, нөлөө, авсан арга хэмжээг issue эсвэл debug log-д тэмдэглэнэ.
- Эрсдэлийг бүрэн арилсан гэж зөвхөн шалгаж баталгаажуулсны дараа тэмдэглэнэ.

## Дүгнэлт

Төслийн явцад цаг, интернэт, Git, ойлголт болон хамрах хүрээтэй холбоотой эрсдэл гарч болно. Эрсдэл бүрд хариуцах хүн болон урьдчилан авах арга хэмжээг тодорхойлсон.
